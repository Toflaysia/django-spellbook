SPELLBOOK — ЗАПУСК В DOCKER ЧЕРЕЗ VS CODE

1. ПОДГОТОВКА
Если Docker Desktop уже установлен, открой его. Второй раз устанавливать не нужно.
Если его нет: https://docs.docker.com/desktop/setup/install/windows-install/
Используется режим Linux containers и WSL 2. Дождись готовности Docker Engine.
После первой установки Docker перезапусти VS Code.

2. УСТАНОВКА ФАЙЛОВ ПРОЕКТА
Скачай setup_docker.py и положи рядом с manage.py.
Открой setup_docker.py в VS Code и нажми ▶ Run Python File.
После сообщения «Готово» появятся Dockerfile, compose.yaml, папка docker,
контейнерные настройки, run_docker.py и stop_docker.py.
Установщик добавляет конфигурацию; Docker Desktop отдельно он не устанавливает.

3. ПЕРВЫЙ ЗАПУСК
Останови обычный сервер Spellbook — в его терминале нажми корзину.
В VS Code открой run_docker.py и нажми ▶ Run Python File.
Сначала скачаются образы и установятся зависимости; это может занять несколько минут.
После сообщения «Готово» открой http://127.0.0.1:8000/
Пользователи, персонажи, заклинания и изображения должны остаться прежними.
Если порт 8000 занят, закрой старый сервер и повтори запуск.

4. ГДЕ ПОСМОТРЕТЬ КОНТЕЙНЕРЫ
Docker Desktop → Containers → spellbook.
В группе три сервиса:
  web       — Django через Gunicorn;
  proxy     — Nginx, страница сайта, стили и изображения;
  reminders — проверка email-напоминаний раз в минуту.
Логи доступны внутри каждого сервиса во вкладке Logs.
У сервиса web миграции и сборка статики выполняются перед запуском сервера.
Остальные сервисы ждут готовности web.

5. ОСТАНОВКА И ОБНОВЛЕНИЕ
Для остановки открой stop_docker.py и нажми ▶ в VS Code.
Контейнеры работают в фоне; закрытие терминала запуска их не останавливает.
При следующем запуске используй run_docker.py: он пересоберёт образ из текущего кода.
Закрытие или остановка Docker Desktop отключает сайт и отправку напоминаний.

6. ГДЕ ХРАНЯТСЯ ДАННЫЕ
db.sqlite3           — прежняя база в корне проекта;
media/               — прежние изображения;
email_settings.json  — прежние настройки SMTP;
secret_key.txt       — прежний ключ приложения;
.docker-static/      — автоматически собранные стили и скрипты.

Код приложения копируется в образ. Папка проекта подключается отдельно в /data,
чтобы SQLite и её журнал транзакций использовались совместно с worker напоминаний.
Nginx получает эту папку только для чтения и раздаёт из неё лишь media и статику.
Пароли, ключ, база и изображения исключены из сборки образа.
Не запускай обычный сервер и Docker-версию одновременно с одной базой.
Для копирования проекта вместе с актуальными данными сначала останови контейнеры.

7. ПРОВЕРКА ПОСЛЕ ПЕРВОГО ЗАПУСКА
Войди прежней учётной записью. Открой персонажа и карточку заклинания.
Проверь стили, портреты и аватар. Измени заметку или создай тестового персонажа.
Останови контейнеры, запусти заново и убедись, что изменение сохранилось.
Для email проверь подтверждённый адрес и включённое напоминание на ближайшее время.
В течение минуты после наступления времени worker должен обработать план.
При ошибках SMTP смотри Logs сервиса reminders. VPN может влиять на доступ к SMTP.

8. ГРАНИЦЫ ПРОВЕРКИ
Выполнены: проверка compose.yaml официальным Docker Compose, тесты запуска,
тесты приложения, проверка настроек и запуска Gunicorn.
Docker Engine в среде подготовки недоступен. Полную сборку и запуск всех трёх
контейнеров нужно впервые проверить на твоём компьютере по пунктам выше.
Эта конфигурация публикует порт только на 127.0.0.1. Для размещения в интернете
отдельно настраиваются домен, HTTPS, разрешённые хосты и резервное копирование.
